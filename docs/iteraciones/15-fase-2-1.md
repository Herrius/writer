# Iteración 15 — Fase 2.1: creación de proyectos desde la GUI

- **Fecha:** 2026-10-21
- **Alcance:** crear un proyecto desde cero sin usar la CLI.
- **Estado:** implementado; pendiente pipeline de revisión.

## 1. Qué se añade

- Comando Tauri `crear_proyecto(ruta, titulo, autor, idioma, notasIniciales)`
  sobre `Project::init`.
- Asistente en la pantalla de bienvenida:
  - título, autor e idioma (`es`/`en`);
  - carpeta padre mediante diálogo nativo;
  - nombre de carpeta editable, derivado del título;
  - casilla para crear notas iniciales de personajes, tramas y lugares.
- Al crear:
  - se valida que el título y la carpeta sean válidos;
  - se crea el proyecto con Libro 1 / Capítulo 1 / Primera escena;
  - se crean las tres notas si la casilla está activa;
  - se abre el proyecto y se muestra un mensaje;
  - se guarda en **Proyectos recientes** (`localStorage`, máximo 8).
- En la demo de navegador el asistente explica que la creación requiere la app
  de escritorio; no simula escritura en disco.
- E2E de navegador del asistente y prueba Rust del comando con/sin notas.

## 3. Corrección de seguridad

La security review de la Fase 2.1 encontró que `Project::init` aceptaba rutas
como `a/..`, vacías o enlazadas. Se movió la validación al backend:

- la ruta se resuelve contra el padre canónico y debe nombrar una carpeta;
- se rechazan componentes `.` y `..`, destinos enlazados, no vacíos o que
  escapen del padre;
- el nombre pasa por `validar_ruta_relativa` (controles, reservados de Windows,
  `CONIN$`/`CONOUT$`, espacios iniciales y puntos/espacios finales);
- `Log::crear_vacio` exige un padre real y rechaza logs enlazados/no regulares;
- los recientes validan tipos, color y longitudes al leer `localStorage`;
- se añadieron regresiones de rutas inválidas, destinos no vacíos y enlaces.
