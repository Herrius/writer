## 1. Qué se implementó

### 3.1 Control de cambios local

- Sidecar `.escritor/cambios/<ULID>.json` con cuerpo base, propuesta, autor,
  fecha, revisión y hash base.
- Un cambio pendiente por documento; las ediciones sucesivas actualizan la
  misma propuesta.
- Modo **Proponer cambios** en el panel lateral: el autosave registra la
  propuesta, no el documento.
- Diff lado a lado y aceptación/rechazo explícitos.
- Aceptar usa una transacción normal con CAS sobre `baseHash`; rechazar solo
  elimina el sidecar.
- Sidecars corruptos se apartan a cuarentena y no bloquean el proyecto.
- El estado de guardado muestra `cambio propuesto`.

### 3.2 Comparación de versiones

- Módulo `diff` por líneas con prefijo/sufijo comunes, LCS y fallback para
  documentos desproporcionados.
- Comparación de un documento actual contra el contenido posterior a una
  revisión del historial.
- Botón **Comparar con el documento actual** en el historial y diff lado a lado
  en el mismo panel.

## 3. Pruebas

```text
cargo test --workspace --all-targets --locked   74 unit + 41 integración + 25 CLI
cargo test desktop                              8/8
pnpm typecheck                                  OK
pnpm ui:test                                    65/65
pnpm exec playwright test e2e/fase-3-1-cambios.spec.ts   3/3
```

Casos cubiertos:

- proponer, actualizar y aceptar un cambio;
- rechazar sin tocar el documento;
- conflicto si el hash base cambió;
- comparación de una revisión con el documento actual;
- diff con inserciones, borrados, numeración y textos vacíos;
- sidecar corrupto a cuarentena.

## 4. Límites

- El cambio es el documento completo; no hay aceptación por hunk ni sugerencias
  inline en el Markdown.
- No hay fusión de tres vías ni autoría multiusuario.
- La comparación de proyecto completo queda fuera de v1.
- El diff es por líneas.
